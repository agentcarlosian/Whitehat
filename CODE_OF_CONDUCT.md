# Community conduct

Whitehat welcomes contributions that help independent researchers perform
careful, authorized security work. Participation should keep the project useful,
safe, and understandable for people with different backgrounds and experience.

## Expected conduct

- Discuss code, evidence, and tradeoffs directly without attacking people.
- Give reviewers enough context to reproduce a change with owned or synthetic
  inputs.
- Respect stated research scope, privacy, licensing, and attribution boundaries.
- Accept corrections when evidence changes a conclusion.
- Keep credentials, private program material, personal data, and real-target
  evidence out of public issues, pull requests, discussions, and fixtures.

## Unacceptable conduct

Harassment, discrimination, threats, doxxing, sexualized attention, sustained
personal attacks, deliberate disruption, and publishing another person's private
information are not acceptable. Neither is pressuring contributors to run unsafe
or unauthorized security tests.

## Scope and enforcement

These expectations apply in Whitehat's repository and project-controlled
community spaces. Maintainers may edit or remove contributions, limit
participation, or report platform abuse when conduct puts people or the project at
risk. Enforcement decisions should be proportionate and should avoid exposing
private reports.

For a project-specific conduct concern, open a content-free issue asking for a
private maintainer channel. Do not place personal details or evidence in that
issue. Use GitHub's abuse-reporting tools for threats, doxxing, or platform-wide
abuse. No response-time commitment is promised.
